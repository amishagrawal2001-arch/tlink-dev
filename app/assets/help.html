Getting Started

Click the + button in the tab bar to open a new connection. Use the Session Manager panel (right sidebar) to browse saved profiles.

Quick-connect: type user@hostname in the command palette (Cmd+Shift+P).

The left dock bar provides quick access to: API Client, Help, and Settings.

SSH

Creating a Connection

Go to Settings → Profiles & connections → + → select SSH. Enter host, port, username, and auth method.

The Test Connection button verifies connection without opening a tab.

Connection Progress

The terminal shows 4-phase progress:

1/4 Connect → 2/4 Key Exchange → 3/4 Auth → 4/4 Ready

Connection Health

• GreenConnected and healthy
• YellowConnected but stale (no recent data)
• RedDisconnected

Auth Methods

Supported: Password, Public Key, SSH Agent, Keyboard Interactive.

Set priority order in profile → Advanced → Authentication Order.

Port Forwarding

Click the plug icon in the SSH toolbar. Supports local, remote, and dynamic (SOCKS5) forwarding.

API Client

Click the globe icon in the left dock bar or tab bar toolbar.

Making Requests

1. Select HTTP method (GET, POST, PUT, DELETE, etc.)

2. Enter the URL

3. Add headers, body, or auth as needed

4. Click Send or press Enter

Response appears on the right with status, timing, formatted JSON, and headers.

Collections

Save requests for reuse: Collections tab → Create collection → click save icon.

Click a saved request to load it back. All fields (URL, headers, body, auth) are preserved.

Tlink Studio (Code Editor)

A Monaco-powered code editor tab that opens alongside your terminals. Click the file-pen icon in the left dock (labeled Tlink Studio) to open it.

What it does

Open local filesFile → Open, drag & drop onto the tab, or Cmd+O
Open remote filesIn an SFTP panel, double-click a text file — opens a Studio tab over the remote path and saves back over SFTP
Multi-tab editingEach open file is its own sub-tab inside the Studio window; Cmd+W closes the current file, not the whole Studio tab
Syntax highlightingAuto-detected from file extension; 50+ languages out of the box
Find / ReplaceCmd+F / Cmd+Option+F, regex mode supported
Multiple cursorsCmd+Click to add a cursor; Cmd+D to select next occurrence

Save behavior

Cmd+S saves. For remote files, the save round-trips over the same SFTP session you opened from — if the SSH connection has dropped, Studio prompts to reconnect before writing. Unsaved files show a dot on the tab; closing prompts to save.

AI in the editor

When the AI Assistant is configured (Settings → AI Assistant), Studio surfaces inline explain / fix actions from the right-click menu — selects code, sends it to the configured provider, returns suggestions inline or in the AI sidebar. Works with any AI provider, not just cloud ones — Ollama / vLLM / Tabby all route through the same path.

Limits

Studio isn't a full IDE — no language-server integration, no debugger, no project tree. For heavy editing use the IntelliJ Bridge or Copilot Agent to keep your real IDE in the loop; Studio is for quick edits without tab-switching to another window.

RDP (Remote Desktop)

Connect to Windows / Linux-XRDP desktops from a tab. NexTerm bundles FreeRDP on macOS — no extra install needed. Falls back to Microsoft Remote Desktop if FreeRDP is unavailable.

Create a profile

Settings → Profiles & connections → + → RDP. Fill in host, port (default 3389), username, password or credential.

Common options

FieldWhat it does
DomainAD domain for DOMAIN\user logins
ResolutionFixed (e.g. 1920×1080) or auto-fit to window
Color depth16 / 24 / 32 bit — lower for slow links
Audio redirectionPlay remote audio on local speakers
Clipboard / drive shareCross-session clipboard; mount a local path as \\tsclient\<name>
GatewayRD Gateway hostname if you go through one

During a session

Keyboard shortcuts are sent to the remote host while the RDP tab has focus. The Send Ctrl+Alt+Del button is in the tab toolbar. Drag the tab to split-view to work alongside a terminal.

Telnet

Legacy plain-text connections for gear that still speaks Telnet (switches, routers, console servers, old print servers). No encryption — use only on trusted networks.

Create a profile

Settings → Profiles & connections → + → Telnet. Enter host and port (default 23). Optional: auto-send login string after a banner pattern matches.

Auto-login

For devices that prompt for user / password on raw Telnet, add an Expect / Send pair under Advanced:

ExpectSend
Username:admin\n
Password:{password}\n

{password} pulls from the profile's saved password field; never embed the literal password in the Send string.

Encoding / line mode

Advanced → Character encoding: pick UTF-8, Latin-1, GBK, or Shift-JIS for old regional consoles. Line mode toggles between raw-byte and line-buffered behavior — flip if your device echoes double characters or drops input.

Serial

Connect to anything on a USB-serial adapter: network-gear console ports, microcontrollers, bench instruments. Uses the OS's serial drivers directly — no extra software.

Create a profile

Settings → Profiles & connections → + → Serial. Pick a port from the dropdown (refreshes on plug/unplug) and set:

FieldTypical value
Baud rate9600 (routers/switches), 115200 (MCUs, most modern consoles), 57600 (older gear)
Data bits8 (almost always)
ParityNone (almost always); Even/Odd for some legacy devices
Stop bits1
Flow controlNone; set to Hardware (RTS/CTS) if the device requires it

Finding the port

macOS / Linux: ls /dev/tty.* /dev/ttyUSB* /dev/ttyACM*. Typical names: /dev/tty.usbserial-XXXX, /dev/ttyUSB0, /dev/ttyACM0.

Windows: Device Manager → Ports (COM & LPT). Use COM3, COM4, etc.

Troubleshooting

Port not in dropdownmacOS may need the FTDI / CH340 / Silicon Labs driver for the adapter. Unplug / replug and hit refresh.
Permission deniedLinux: add your user to the dialout group (sudo usermod -aG dialout $USER, then log out / in).
Garbled outputWrong baud rate or encoding. Try 115200 first; try 9600 second.
No response to keystrokesFlow control mismatch. Flip to Hardware or None.

Copilot / VS Code Agent

NexTerm ships an MCP server (the Copilot Agent, also known as the VS Code Agent — same plugin) so an external AI client like VS Code's Copilot Chat can drive your terminal sessions: read the buffer, run commands, inspect history, abort stuck jobs.

One-time setup (inside NexTerm)

1. Open Settings → Copilot Agent.

2. Set the port (default 3001; change only if it collides).

3. Toggle Start on Boot if you want the server always available.

4. Toggle Pair Programming Mode on — a confirmation dialog pops up in NexTerm before the AI runs any command. Strongly recommended.

5. Click Start Server. Status indicator should flip to • Running. Server URL becomes http://localhost:3001/sse.

One-time setup (inside VS Code)

Edit your MCP config (usually ~/.config/Code/User/globalStorage/mcp.json on Linux/macOS; equivalent on Windows) and add:

{
  "servers": {
    "nexterm": {
      "url": "http://localhost:3001/sse",
      "type": "http"
    }
  }
}

Reload VS Code. Copilot Chat (or any other MCP client — Claude Desktop, Cursor, Zed) will now see the NexTerm tools.

Stdio alternative: if your client prefers stdio, the Copilot Agent settings page shows a path to the local node entry — add it as { "type": "stdio", "command": "node", "args": ["<path-from-settings>"] }.

Things you can ask the AI

AskTool used
"What's in my first terminal session?"get_terminal_buffer
"List all my SSH sessions"get_ssh_session_list
"Run npm test in session 1"execute_command (approval dialog if Pair Mode is on)
"What commands are still running?"list_running_commands
"Show me the output of the last command"get_command_output
"Abort the stuck process in session 0"abort_command (sends Ctrl+C)

Toolbar buttons the plugin adds

Open Copilot ChatOpens VS Code directly
Command HistoryBrowse past commands + outputs
Running CommandsMonitor / abort active commands across all sessions

Safety notes

Leave Pair Programming Mode on. An AI can issue rm -rf / just as easily as ls; the approval dialog is the last line of defense.

The AI Assistant's risk-assessment flow (Low / Medium / High / Critical bands with password protection on high-risk) applies to commands that arrive via MCP too.

Troubleshooting

Server won't startPort collision (try 3002), firewall, or stale process on old port. Check NexTerm logs.
VS Code doesn't see the serverReload VS Code after editing mcp.json. Verify with curl http://localhost:3001/sse — should return an SSE handshake.
Commands silently don't runThe MCP tools operate on existing terminal tabs — open at least one session before the AI tries to drive it.
Approval dialog never appearsCheck Pair Programming Mode is enabled, and the NexTerm window has focus.

IntelliJ Bridge

The sibling plugin to the Copilot / VS Code Agent — same idea (let an external IDE drive your terminal sessions over an MCP-style bridge) but scoped to IntelliJ-family editors (IDEA, PyCharm, WebStorm, GoLand, CLion, Rider, etc.). Use this when your day job is in IntelliJ and you want to ask the IDE's built-in AI to work with your live terminal buffers.

One-time setup (inside NexTerm)

1. Open the left dock, right-click the IntelliJ icon → settings, or find the bridge under Settings → IntelliJ Bridge.

2. Pick the IntelliJ port (default 63342, matching IntelliJ's built-in HTTP server).

3. Click Start Bridge. Status flips to • Running.

One-time setup (inside IntelliJ)

1. Settings → Tools → Startup/Shutdown Tasks (or Plugins if the matching IntelliJ-side plugin is installed).

2. Enable IntelliJ's built-in HTTP server (Settings → Build, Execution, Deployment → Debugger → Built-in server, port 63342).

3. If you're using AI Assistant inside IntelliJ (JetBrains AI or a third-party plugin), configure it to discover NexTerm at http://localhost:63342/tlink.

Click the left-dock icon to open IntelliJ

The laptop-code icon in the left dock opens IntelliJ on the current workspace (if one is detected). Without a detected project, it opens the most recent project. On first click NexTerm asks for the IntelliJ binary path; pick the idea / pycharm / etc. command-line launcher.

What you can ask from IntelliJ

The exact surface depends on which IntelliJ AI integration you use. If your IntelliJ plugin is MCP-aware (e.g., recent JetBrains AI builds, Continue.dev in IntelliJ), you get the same tool set as the VS Code Agent: buffer read, command execution with approval, history, running commands, abort. See the Copilot / VS Code Agent section for the full tool list — it applies identically here.

Safety & troubleshooting

Keep Pair Programming Mode on (same toggle as the VS Code Agent — they share the approval flow). If the bridge won't start, verify IntelliJ's built-in server is running (curl http://localhost:63342 should return something) and the port isn't held by another IDE instance.

Tabby (Self-hosted AI)

Tabby here means Tabby ML — the self-hosted, open-source AI coding assistant with an OpenAI-compatible API. (Not the terminal app this codebase forked from.) NexTerm treats it as one of the AI providers in the Assistant, plus ships a dedicated Settings → Tabby Server tab for a streamlined config flow.

Why use it: your prompts and code never leave your machine / private server. Good fit when your org's policy bans sending code to OpenAI / Anthropic / Claude.

Install Tabby (Docker, quickest path)

On a machine with an NVIDIA GPU (or CPU-only for small models):

docker run -it --gpus all -p 8080:8080 \
  -v $HOME/.tabby:/data \
  tabbyml/tabby \
  serve --model StarCoder-1B --device cuda

Leave the container running. Tabby listens on http://localhost:8080 by default.

Full install options (CPU-only, Apple Silicon, systemd, k8s) at tabbyml.com/docs/quick-start.

Register an account & get an API token

1. Open http://localhost:8080 in your browser.

2. Create the first admin account (Tabby auto-promotes the first user).

3. Go to Settings → General → Credentials (or equivalent) and copy your API token.

Full walkthrough: tabbyml.com/docs/quick-start/register-account.

Configure NexTerm to use Tabby

Two equivalent paths:

Option A — Tabby Server tab (streamlined):

  • Settings → Tabby Server

  • Endpoint: http://localhost:8080 (or your remote Tabby URL)

  • API token: paste the one from the Tabby UI

  • Pick completion / chat / embedding models (dropdowns auto-load from Tabby's catalog)

Option B — AI Assistant provider tab:

  • Settings → AI Assistant → Providers → select Tabby

  • Same fields (base URL, API key, model); shares storage with Option A.

What you get

ChatAsk the AI sidebar questions; responses come from your Tabby server instead of a cloud API.
CompletionIf you wire the completion model, Tabby drives inline code suggestions.
Command helpThe terminal's AI helpers (explain error, fix command) route through Tabby the same way they route through OpenAI.

Troubleshooting

Connection test failsVerify Tabby is running: curl http://localhost:8080/health. If remote, check firewall / port forwarding.
401 / 403 on requestsAPI token wrong or revoked. Regenerate in Tabby's Settings and re-paste in NexTerm.
Slow responsesSmall CPU-only models (StarCoder-1B) are slow on non-GPU hardware. Use a larger GPU model or smaller context window.
Models dropdown emptyTabby needs at least one model loaded. Check the Tabby UI under Models — see model docs.

API reference (if you're scripting against the same endpoint): tabbyml.com/docs/api.

Session Sharing & WebSocket

Three related left-dock items let you share terminal sessions with a teammate or let NexTerm accept inbound connections from other tools:

Share All Sessions

The share-nodes icon in the left dock. Click it to expose every currently-open terminal tab over a shared-session link. NexTerm opens a local relay, then pops up a URL you can send to another NexTerm user.

The receiver pastes the link into their own Open Shared Session Link dock item (see below) and instantly sees your tabs in read-only form (or read-write if you granted it). Useful for pairing without screen-sharing the whole desktop.

Click the icon a second time to stop sharing; all generated links expire immediately.

Open Shared Session Link

The link icon. Paste a share URL that a teammate sent you. NexTerm connects to the relay and adds their live sessions as tabs in your workspace. You see their tabs alongside your own; closing the linked tab disconnects you without affecting them.

Permissions are controlled by the sender — if they shared read-only, your keystrokes are dropped. If they granted read-write, you share the input buffer (both of you type into the same stream).

WebSocket Server

The plug icon. Toggles a local WebSocket endpoint that other tools — scripts, browser extensions, another NexTerm instance — can connect to for programmatic access to terminal sessions.

Icon states:

plugServer off
power-offServer running — click to stop
spinnerStarting / stopping

Default port is printed in the toast when the server comes up. Configure authentication (token-based) and allowed origins under Settings → WebSocket. The Copilot / VS Code Agent and IntelliJ Bridge both optionally use this transport under the hood.

Safety

Shared session links are unauthenticated past the URL — anyone with the link gets the permissions it was issued with. Treat them like share-tokens: send through a private channel, and stop sharing when you're done pairing.

The WebSocket server binds to 127.0.0.1 by default. Only change that if you know what you're doing (firewall, auth config, the works).
